# 分析算法

## 为什么真实生成

种子只初始化世界生成过程。游戏版本、大小、难度、邪恶类型、秘密世界选项和各生成 Pass 共同决定最后的地形、结构与宝箱。工具因此把本机原版 `TerrariaServer.exe` 当作唯一世界生成器，再读取最终 `.wld`；不复制 Terraria WorldGen 代码，也不声称仅凭 PRNG 推导全部结果。

## 世界文件

读取器验证 Re-Logic 文件签名、世界类型、版本、分区指针、Header、Tile RLE 边界和 Chest 分区边界。版本不在 269–326 时立即停止。输入流为只读并允许游戏共享读写，因此分析不会改变存档。

Tile 网格以 X-major 紧凑数组存储：tile 使用 `ushort`，墙只保存分析所需类别，液体保存水/岩浆/蜂蜜/微光类别，Frame 只保留箱子和少数重要对象。

## 邪恶区域与肉前自由蔓延

当前腐化/猩红区域在 8×8 网格中按邻接连通，避免逐块 BFS 的高内存和时间成本。

肉前自由蔓延闭包单独计算：

1. 在地表上下有限的真实物块带中逐列寻找邪恶源与肉前可传播材料。
2. 普通草/泥土以及已有邪恶草参与暴露土壤通道；已有邪恶丛林草可沿相邻泥土通道继续传播。
3. 草只按八邻域的直接相邻传播，不套用困难模式三格转换。
4. 对地表空气使用 12 格的保守荆棘生长预算；只有再次接触可感染土壤后预算才会重置，不能沿空气无限传递。
5. 向日葵只保护其正下方物块，不被夸大成贯穿世界的屏障。
6. 只统计能由初始肉前传播源到达的通道，并报告最大与合计水平宽度。

这回答的是“肉前放任扩散会占据多宽地表走廊”，不会错误地把困难模式石头/沙/冰三格感染全部套到肉前。

## 结构与资源

生态和大型结构使用 8×8 类别网格连通分量，应用最小区块阈值去掉噪点。宝箱、Tile/Wall 数量来自世界文件精确计数；多格对象（生命水晶、祭坛、暗影珠）按原版占格折算。

金字塔由大型沙岩砖连通结构识别。真剑冢按 Tile 187 的 3×2 对象、style 17 且只计左上角 Frame；style 17 的 Frame X 起点为 `17 × 54 = 918`。

浮岛会生成与主体分离的装饰云团，天空湖又没有宝箱，因此不能简单按云连通分量或天空箱数量统计。分析器先识别云、雨云、雪云和天域物块，再把水平、垂直间距都不超过 40 格的碎片合并为同一个可见结构；这既保留天空湖，也避免把一座普通浮岛误报成多个。生命树使用同类方法，但只桥接 16 格以内的生命木/树叶碎片。

箱子样式按原版 `frameX / 36` 读取。1.4.5.8 中 `Containers` style 10 是常春藤箱，style 13 才是天域箱；分析器的 0–51 与 `Containers2` 0–37 映射均按原版掉落表核对。锁箱判定则独立使用原版可解锁样式集合。

## 估算获取成本

世界降采样为 8×8 单元，从出生点执行一次 Dijkstra：

- 空气/可穿过装饰成本最低；
- 普通实体物块增加挖掘成本；
- 垂直移动高于水平移动，无支撑的高空路线附加架桥成本，防止寻路不切实际地绕到天空；
- 丛林、邪恶、雪原和沙漠分别累加危险权重，地下沙漠高于地表沙漠；
- 蜘蛛洞、蜂巢、地牢和神庙进一步附加危险/阶段成本；
- 水有轻度惩罚，岩浆有重惩罚；
- 锁金箱、暗影箱、地牢箱、生态箱和神庙另加阶段锁惩罚。

同一次距离场用于全部重要宝箱、生命水晶、地牢、丛林、雪原、沙漠、微光和神庙，不会为每件物品重复寻路。优先队列按累计成本展开；所有实际目标都已确定最低成本后立即停止，不再无条件遍历世界其余部分。最坏复杂度仍约为 `O((W/8 × H/8) log N)`。

## 生成与分析性能

完整世界指标必须等待本机原版 `TerrariaServer` 真正完成所有 WorldGen Pass。只从种子逆推少量随机数的工具虽然非常快，但无法知道最终宝箱内容、相互覆盖后的结构与可通行路线，因此这里只用于研究对照，不作为未经验证的预筛器。

服务端宣布启动后，生成器直接验证世界签名、全部分区指针及位于文件末尾的有效 Footer，然后发送 `exit-nosave`；不再采用固定四次文件长度轮询。进度日志按 10% 分桶，避免 CLI 输出和 WinForms `RichTextBox` 刷新反过来拖慢后台生成。默认仅运行一个、正常优先级的服务端；提高并发属于吞吐换资源，而不是减少单世界工作量。

## 评分

硬条件仅决定合格/淘汰。加权条件把目标附近的满足程度标准化后乘权重；超过目标仍可获得有限额外奖励，偏离目标会降低分数。这样“至少一件”与“越多越好”可以同时表达，又不会让单个数量特别大的指标无限支配总分。
